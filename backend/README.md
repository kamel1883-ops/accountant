# جداره Finance — Backend API

باك إند نظام محاسبي سعودي متعدد المستأجرين (Multi-tenant SaaS): كل عميل (منشأة)
معزول تماماً عن غيره ببيانات مستقلة، بالإضافة إلى بوابة مالك منفصلة لإدارة العملاء
والاشتراكات والإيرادات.

## التقنيات
Node.js + TypeScript + Express + Prisma + PostgreSQL

## التشغيل محلياً

```bash
npm install
cp .env.example .env      # ثم عدّل القيم داخل .env بنفسك (لا ترفعه على GitHub)
npx prisma migrate dev --name init
npm run prisma:seed       # ينشئ أول حساب مالك (Owner) من القيم في .env
npm run dev                # يشغّل السيرفر على http://localhost:4000
```

## البنية

```
src/
  app.ts                  نقطة تجميع كل المسارات (routes)
  server.ts                نقطة تشغيل السيرفر
  middleware/
    auth.ts                توثيق مستخدمي المنشآت (tenant-scoped JWT)
    ownerAuth.ts            توثيق منفصل تماماً لبوابة المالك
  modules/
    auth/                  تسجيل دخول مستخدمي المنشأة
    accounts/               دليل الحسابات (ثنائي اللغة)
    journal/                القيود اليومية + ميزان المراجعة
    invoices/                الفواتير (ترحيل تلقائي للقيد + ضريبة ١٥٪ + QR زاتكا)
    vat/                     الإقرار الضريبي الربعي
    zakat/                   احتساب الوعاء الزكوي
    leads/                   استقبال طلبات صفحة الهبوط (عام، بدون توثيق)
    branches/                إدارة الفروع (أساس تعدد الفروع)
    inventory/               التصنيفات، الوحدات، المستودعات، المنتجات
    stock/                   حركة المخزون، الأرصدة، جرد المخزون (مع تسوية تلقائية)
    owner/                  بوابة المالك: تسجيل دخول، الطلبات، العملاء، الإيرادات
  utils/
    vatCalculator.ts, zatcaQr.ts, zakat.ts, seedAccounts.ts
prisma/
  schema.prisma            نموذج البيانات الكامل
  seed.ts                  ينشئ أول حساب مالك
```

## مبدأ العزل بين المستأجرين (Multi-tenancy)

كل جدول بيانات محاسبي (Account, JournalEntry, Invoice...) مرتبط بـ `tenantId`،
وكل طلب API لمستخدم منشأة يمر عبر `requireAuth`، الذي يستخرج `tenantId` من الـ JWT
نفسه — مو من الطلب — فلا يقدر أي مستخدم يشوف بيانات منشأة ثانية حتى لو حاول.

بوابة المالك (`/api/owner/*`) توثيق منفصل بالكامل (`requireOwnerAuth`، جدول `Owner`
مستقل)، حتى لا يختلط أبداً بمستخدمي المنشآت.

## ما هو ناقص عن قصد في هذي المرحلة (Phase 1)

- **ربط زاتكا الحي (Phase 2)**: التوقيع الرقمي (ECDSA) وشهادة الامتثال (CSID) وربط
  بوابة فاتورة الفعلي. `utils/zatcaQr.ts` يبني بنية البيانات الصحيحة فقط، ويحتاج
  بياناتك الضريبية الحقيقية وشهادتك ليكتمل.
- **واجهة أمامية (Frontend)**: هذا المستودع API فقط. الواجهة (React) تُبنى في
  مرحلة لاحقة تستهلك نفس هذا الـ API.
- **ربط جداره HR**: نقطة `/api/integrations/hr/journal-entry` موجودة كمكان جاهز
  (placeholder) فقط، تُفعَّل عند بناء نظام HR فعلياً.
- اختبارات آلية (tests)، صلاحيات أدق لكل شاشة، وتسجيل تدقيق (audit log).
