# جداره Finance

نظام محاسبي سعودي متعدد المستأجرين (Multi-tenant SaaS)، مع بوابة مالك مستقلة
وصفحة هبوط تسويقية.

## بنية المشروع

```
jadara-finance/
  backend/      Node.js + TypeScript + Express + Prisma + PostgreSQL — الـ API الكامل
  frontend/     React + TypeScript + Vite + Tailwind — تطبيق المحاسبة + بوابة المالك
  marketing/    صفحة الهبوط التسويقية + نسخة العرض التجريبية الأولى (مرجع تصميم فقط)
```

## الترتيب المقترح للتشغيل محلياً

1. ثبّت Node.js 20+ وPostgreSQL (أو `docker compose up -d` لقاعدة البيانات).
2. `backend/`: انسخ `.env.example` إلى `.env`، عدّل `OWNER_EMAIL` و`OWNER_PASSWORD` و`JWT_SECRET`، ثم:
   `npm install` ثم `npm run prisma:push` ثم `npm run prisma:seed` ثم `npm run dev`.
3. `frontend/`: انسخ `.env.example` إلى `.env` ثم `npm install` و`npm run dev`.
4. تطبيق المحاسبة: `http://localhost:5173` — بوابة المالك: `http://localhost:5173/owner-portal`

### دخول بوابة المالك
لا تنشئ حساباً من الواجهة ولا تستخدم «نسيت كلمة المرور» في أول مرة.
ضع بريدك وكلمة المرور في `backend/.env` ثم نفّذ `npm run prisma:seed`، وادخل بنفس البيانات على `/owner-portal`.
بريد المالك الوحيد يُضبط في `backend/.env` عبر `OWNER_EMAIL`. كلمة المرور المحلية ضعها أنت في `OWNER_PASSWORD` قبل `npm run prisma:seed`، ولا ترفع القيمة الحقيقية.

## الحالة الحالية (Phase 1) — وش جاهز ووش لسا

**جاهز وشغّال (يحتاج فقط تشغيل محلي وربط قاعدة بيانات):**
- دليل حسابات ثنائي اللغة، قيود يومية متوازنة، أستاذ عام وميزان مراجعة
- فواتير بترحيل تلقائي للقيد + ضريبة ١٥٪ + بنية QR زاتكا
- الإقرار الضريبي الربعي، احتساب الوعاء الزكوي
- المخزون: منتجات، تصنيفات، وحدات قياس، فروع ومستودعات متعددة، حركة مخزون، وجرد بتسوية تلقائية
- المالية: خزائن نقدية وحسابات بنكية، سندات قبض وصرف بترحيل تلقائي للقيد
- التقارير: مبيعات، مشتريات (حسب العميل/المورد)، مخزون (تنبيه نواقص)، كشف حساب لأي بند بدليل الحسابات
- المبيعات الكاملة: عروض أسعار، أوامر بيع، فواتير، مرتجعات — بدورة مسودة → اعتماد، مع خصم/إرجاع المخزون وترحيل القيد تلقائياً
- نقطة بيع (POS): بيع سريع بضغطة واحدة (فاتورة + قيد + تحصيل نقدي في معاملة واحدة)
- المشتريات الكاملة: طلبات شراء داخلية، أوامر شراء، فواتير، مرتجعات — بنفس دورة المسودة/الاعتماد
- بوابة مالك: صندوق طلبات، تحويل طلب لعميل فعلي، تفعيل/إلغاء الاشتراك، لوحة إيرادات
- صفحة هبوط تسويقية بخطط الاشتراك والسياسات القانونية

**لسا ناقص عن قصد (المرحلة القادمة):**
- مراكز التكلفة، صلاحيات دقيقة لكل شاشة حسب الفرع
- طباعة/تصدير PDF احترافي لكل مستند (عرض سعر، فاتورة، مرتجع) — حالياً نص وجداول فقط
- ربط صفحة الهبوط الفعلي بنقطة `/api/leads` (حالياً منفصلة كملف HTML تجريبي)
- الربط الحي مع بوابة فاتورة/زاتكا (التوقيع الرقمي والشهادات)
- ربط جداره HR (نقطة الاستقبال جاهزة كـ placeholder في الباك إند)
- نشر فعلي على VPS (Docker، Nginx، شهادة SSL)
- اختبارات آلية وتدقيق أمني قبل الإطلاق للعموم


## مسار العميل الجديد (تسجيل ← عرض سعر ← تحويل ← تفعيل)

1. العميل ينشئ حساباً من `/register` (اسم المنشأة، الرقم الموحد، الجوال، البريد، النشاط، الباقة).
2. النظام يولّد **عرض سعر PDF واحداً** (العرض + بيانات التحويل + شهادة الآيبان + الختم) ويرسله لبريده، وفيه: أرسل إيصال التحويل إلى `info@jadara-finance.com`.
3. العميل يدخل من `/login` ويرى حالة طلبه ويحمّل عرض السعر (`/account`)، ويستعيد كلمة المرور من `/forgot-password`.
4. أنت في بوابة المالك (`/owner`) تؤكد الاشتراك: الباقة، المدة، الخصم، **المبلغ المستلم** وتاريخه. النظام ينشئ المنشأة وأول مستخدم ADMIN (بنفس بريد العميل وكلمة مروره)، ويسجّل الدفعة في قائمة التدفق النقدي، ويولّد **العقد** (12 مادة) ويرسله للعميل.

قوالب المستندات: `backend/templates/quote.html` و`contract.html`. بيانات الشركة والآيبان والأسعار في `src/modules/documents/company.ts` و`plans.ts`.

### متطلبات التشغيل الخاصة بالمستندات والبريد
- ضبط `SMTP_*` في `.env` لإرسال البريد فعلياً (بدونها تُطبع الرسائل في سجل السيرفر فقط).
- على الـ VPS: `apt install fonts-noto-core chromium` (أو ما يحتاجه Puppeteer) وضع خط Tajawal إن أردت مطابقة شكل نماذجك تماماً.
- `npx prisma migrate dev --name customer_quotes_contracts` بعد سحب هذا التحديث.


## الروابط بعد النشر (وكيف تدخل بوابة المالك)

| الرابط | الوظيفة |
|---|---|
| `https://نطاقك/` | صفحة الهبوط (`marketing/landing-page.html`) |
| `https://نطاقك/register` | إنشاء حساب عميل |
| `https://نطاقك/login` | دخول العملاء (نفس الشاشة لمن فُعّل اشتراكه ولمن ينتظر التفعيل) |
| `https://نطاقك/forgot-password` | استعادة كلمة المرور |
| `https://نطاقك/account` | صفحة العميل قبل التفعيل (حالة الطلب + تنزيل عرض السعر والعقد) |
| **`https://نطاقك/owner`** | **بوابة المالك** (دخول منفصل تماماً عن العملاء) |

محلياً (أثناء التطوير): التطبيق `http://localhost:5173` وبوابة المالك `http://localhost:5173/owner`.

**حساب المالك:** ضع `OWNER_SEED_EMAIL` و`OWNER_SEED_PASSWORD` في `backend/.env` ثم شغّل `npm run prisma:seed` مرة واحدة — يُنشأ حسابك ويخزَّن مشفّراً. لا تكتب بياناتك في أي ملف يُرفع على GitHub.

إعداد Nginx جاهز للنسخ في `deploy/nginx.conf.example`.

## الفوترة الإلكترونية (زاتكا)

من شاشة **الفوترة الإلكترونية** داخل المنشأة:

1. أدخل الرقم الضريبي (15 رقماً) واسم المنشأة واختر Sandbox ثم ولّد CSR.
2. أدخل OTP من بوابة فاتورة (في الساندبوكس غالباً `123345`) لإصدار شهادة الامتثال CCSID.
3. أرسل فواتير الامتثال الستة.
4. أصدر شهادة الإنتاج PCSID. بعدها الفواتير المبسّطة تُبلَّغ تلقائياً، والقياسية (رقم ضريبي للعميل) تذهب للتخليص.

الإنتاج الحي يحتاج حساباً حقيقياً على فاتورة وOTP حقيقي، وليس رموز الساندبوكس.

## النظام المحاسبي (المحرّك والقوائم)

**دليل الحسابات:** خمسة حسابات رئيسية — الأصول، الخصوم، حقوق الملكية، المبيعات، المشتريات — وتحتها مجموعات وحسابات فرعية جاهزة (نحو 60 حساباً)، ويمكن فتح حسابات فرعية غير محدودة تحت أي حساب من صفحة «دليل الحسابات». كل حساب يحمل **نوعاً وتصنيفاً فرعياً** (نقدية، أصل متداول، مصروف تشغيلي، مردودات…)، ومن هذين تُبنى القوائم المالية آلياً بدل الاعتماد على أرقام الحسابات.

**القيود اليومية:** قيد مركّب بأي عدد من الأطراف (20 طرفاً أو أكثر)، لكل سطر بيانه الخاص. لا يُحفظ أي قيد إلا بعد التحقق من: وجود طرفين على الأقل، أن الحسابات موجودة وغير تجميعية ونشطة، ألا يكون السطر مديناً ودائناً معاً، وأن المدين يساوي الدائن. لكل قيد رقم تسلسلي و**مستند طباعة A4** فيه الأطراف والإجماليات ومكان التوقيع والختم.

**ميزان المراجعة:** بأعمدة رصيد أول المدة وحركة الفترة والرصيد الختامي، تفصيلي أو إجمالي، مع اختصار «هذا الشهر» للمراجعة الشهرية.

**القوائم المالية الأربع:** قائمة الدخل، قائمة المركز المالي، قائمة التدفقات النقدية (الطريقة غير المباشرة)، وقائمة التغير في حقوق الملكية — كلها من محرّك أرصدة واحد (`utils/accounting.ts`) فتتطابق أرقامها دائماً.

**أرصدة أول المدة والحسابات الختامية:** من صفحة «الفترات المالية»: أنشئ سنة مالية، سجّل أرصدة أول المدة كقيد افتتاحي، ثم عاين قيد الإقفال ونفّذه ليصفّر حسابات المبيعات والمشتريات ويرحّل النتيجة إلى حقوق الملكية. السنة المقفلة يُمنع الترحيل فيها، ويمكن إعادة فتحها.

**ضمان صحة المخرجات:** صفحة «فحص سلامة البيانات» تتحقق من توازن الميزان، وسلامة كل قيد على حدة، وعدم وجود سطور على حسابات محذوفة أو تجميعية، وصحة المعادلة المحاسبية. ويوجد اختبار محاسبي آلي:

```bash
npm run test:accounting
```

يغطي: توازن القيود، ميزان المراجعة، قائمة الدخل، المعادلة المحاسبية، مطابقة التدفقات النقدية، وتصفير الحسابات بعد الإقفال.

**طباعة المستندات:** قيد اليومية، فواتير المبيعات والمشتريات وعروض الأسعار والمرتجعات — بصيغة A4 مع رمز QR على الفواتير الضريبية وفق متطلبات الهيئة.

> بعد سحب هذا التحديث: `npx prisma migrate dev --name accounting_core` ثم `npm install` (أُضيفت حزمة qrcode).
> تنبيه: تغيّرت أرقام بعض الحسابات في الدليل (مثل المخزون والمصروفات)، فالمنشآت التي عليها بيانات سابقة تحتاج ترحيلاً يدوياً للأرصدة.


## اللغة والتواريخ والطباعة

**ثنائية اللغة:** النظام يعمل بالعربي والإنجليزي بالكامل، والتبديل بزر واحد أسفل القائمة الجانبية. عند التبديل يتغيّر اتجاه الصفحة (RTL/LTR) وكل النصوص وأسماء الحسابات (كل حساب له `nameAr` و`nameEn`). اللغة تُحفظ في المتصفح، والمستندات المطبوعة تصدر بنفس لغة الواجهة عبر `?lang=ar|en`. قاموس الواجهة كله في ملف واحد: `frontend/src/i18n.tsx`.

**التواريخ:** كل التواريخ في الشاشات والتقارير والمستندات **ميلادية** بصيغة `YYYY-MM-DD` عبر دالة واحدة (`gdate`)، والأرقام لاتينية لتطابق المطبوع. التاريخ الهجري يظهر في عقد الاشتراك فقط (إلى جانب الميلادي) لأنه مستند قانوني.

**الطباعة:** كل تقرير وقائمة فيها زر طباعة، ومعها ورقة أنماط طباعة تخفي القائمة الجانبية والأزرار وتضيف ترويسة فيها اسم المنشأة واسم التقرير والفترة وتاريخ الطباعة. المستندات الرسمية (قيد اليومية، الفواتير، المرتجعات، عروض الأسعار) تُطبع كـ PDF من الخادم بصيغة A4 مع الختم ورمز QR على الفواتير الضريبية.

> **ملاحظة:** حُذفت شاشة «الفواتير (قديم)». كانت من بداية المشروع وتسجّل فاتورة بمبلغ إجمالي فقط بدون أصناف ولا أثر على المخزون، وحلّت محلها شاشتا المبيعات والمشتريات الكاملتان.

## بوابة المالك: الوصول والأمان

**كيف تصل لها؟** اكتب في المتصفح: `https://دومينك/owner-portal` — الرابط غير موجود في صفحة الهبوط عمداً، فلا يعرفه إلا أنت. تقدر تغيّره لمسار سرّي بتعديل `VITE_OWNER_PATH` في الفرونت إند و`OWNER_PATH` في الباك إند (مثلاً `/portal-x7k2`) ثم إعادة بناء الفرونت إند. المسار الخفي مجرد طبقة إضافية؛ الحماية الفعلية هي البريد السرّي وكلمة المرور.

**البريد السرّي:** في `backend/.env` ضع `OWNER_EMAIL` و`OWNER_PASSWORD` ثم شغّل `npm run prisma:seed`.
- النظام لا يعرف إلا هذا البريد كمالك؛ لا يوجد تسجيل ولا إنشاء حساب للمالك، وأي بريد آخر يُعامل كأنه غير موجود.
- الـ seed يحذف أي حساب مالك آخر من قاعدة البيانات.
- استعادة كلمة المرور من `/owner-portal/forgot`: يصل الرابط (صالح 30 دقيقة) إلى `OWNER_EMAIL` فقط، والرد للجميع واحد، فلا يُكشف أن البريد صحيح أو خاطئ. يحتاج إعداد `SMTP_*`.
- محاولات الدخول والاستعادة محدودة (8 كل 15 دقيقة لكل عنوان)، ولا يُقبل توكن مالك إلا ببريد المالك المعتمد.
- بريد المالك لا يمكن استخدامه في تسجيل عميل.

## أكواد الخصم

من بوابة المالك ← أكواد الخصم: نسبة ٪ أو مبلغ ثابت، لباقة معينة أو للكل، بحد أقصى للاستخدام وتاريخ انتهاء، مع تعطيل/حذف.
العميل يكتب الكود في صفحة التسجيل (يتحقق منه ويعرض الإجمالي فوراً)، فيظهر الخصم في **عرض السعر** وينتقل تلقائياً إلى **العقد** عند تأكيد الاشتراك (تقدر تعدّل قيمته وقت التأكيد). الخصم قبل الضريبة، والضريبة 15٪ تُحسب على الصافي.

## نظرة عامة في بوابة المالك

عدد الطلبات المعلّقة، العملاء في التجربة (مع الأيام المتبقية)، المشتركون الفعّالون، العقود التي تنتهي خلال 60 يوماً، والاشتراكات المنتهية. من «العملاء المشتركون» تجدد الاشتراك أو تحوّل التجربة إلى اشتراك وتسجّل الدفعة. الاشتراكات المنتهية تتحول تلقائياً إلى «منتهية» ويُمنع دخول أصحابها.

بعد سحب هذا التحديث: `npx prisma migrate dev --name discount_codes_owner_reset`
